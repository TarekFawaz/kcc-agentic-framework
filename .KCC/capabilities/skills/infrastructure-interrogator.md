# Infrastructure Interrogator

Interrogate infrastructure **and packaging** concerns for: <ARGS>

This skill covers two domains by default: (1) **deployment / infrastructure**
and (2) **packaging** - how each component is built into a distributable
artifact (containerization, registries, artifact types, versioning/tagging,
distribution channels, SBOM/signing). Packaging is not optional and is not
left to the deploy stage; it is interrogated here.

## When this is in scope

Run this skill for any **deployable, production-ready, API, service, cloud,
on-prem, hybrid, containerized, distributed, or otherwise shippable** work -
not only when "cloud" is mentioned explicitly. If the thing gets built into an
artifact, run anywhere other than the author's machine, exposed over a network,
or handed to anyone to install/run, infrastructure + packaging interrogation
applies. Skip only for pure local prototypes/throwaway scripts with no
distribution. (Automatic firing from `auto` / idea-interrogator is handled
elsewhere; this section states the skill's own applicability.)

## Steps

1. Resolve `<ARGS>` to an idea folder, technical brief, or spec request.
2. Delegate to **infrastructure-planner**.
3. Require `InfrastructureDecisionBrief.md` - with BOTH a deployment shape and a
   `## Packaging` section - for cloud, on-prem, K8s, production, scale,
   reliability, paid-service, containerized, or distributed/published work.
4. Confirm packaging is covered per component: containerization (yes/no, base
   image, multi-stage), registry, artifact type, version/tag scheme,
   distribution channel(s), SBOM/signing, and artifact -> deploy-target mapping.
5. Pass candidate guardrails and quality gates to architect and spec-writer.
6. If confidence is below the active threshold, invoke `/critical-human-gate`.

## Feeds the deploy stage

The brief's `## Packaging` section is a required input to the optional deploy
stage. Per [[deployment]], packaging decisions drive the pipeline's
build/package stages generated by **infrastructure-implementer** via
`/spec-deploy`.

## Constraints

- Do not provision or mutate infrastructure.
- Do not build, publish, sign, or push artifacts/images.
- Never assume production deployment, cloud spend, SLOs, DR commitments, or
  public artifact distribution.
