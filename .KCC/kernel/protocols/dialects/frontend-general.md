# Frontend General Dialect

Use when the frontend framework is unknown or mixed.

## Coding
- Prioritize accessible controls, responsive layout, stable dimensions, clear state, and maintainable component boundaries.

## Review
- Check visual hierarchy, keyboard flow, text fit, responsiveness, accessibility, asset loading, and performance.

## Bug Fix
- Reproduce visually or with interaction steps, patch narrowly, verify desktop and mobile viewports.

## Testing
- Use available unit/component/e2e tests plus screenshot or browser smoke checks.

## Docs
- README must include run commands, user flows, routes/screens, and asset credits.

## Complexity
- low: junior-safe UI tweak.
- medium: mid-level flow.
- high: senior state/performance/accessibility.
- extra-high: principal-expert design system or complex interaction platform.
