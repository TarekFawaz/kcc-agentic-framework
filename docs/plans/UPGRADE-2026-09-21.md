# KCC Upgrade 2026-09-21

This document is for porting these changes into the main KCC repo. The
baseline is `KCC Repo/.KCC` as it stood on 2026-09-21. Against that
baseline: **58 files changed, 33 new entries** (the new folders `refs/`, `hooks/`, and
`pipelines/quality-gate/` count once each; sections 3-4 plus the `kcc-run`
files in section 8), 0 removed. Every path below is relative to `.KCC/`.
This file and `PLAN-distribution-mcp.md` are documentation for maintainers;
they don't need to ship in cells.

## 1. What changed and why

| # | Theme | Outcome |

| B | Model and effort profiles | Agents gain an `effort:` field. The model classes map to `opus` / `sonnet` / `haiku` aliases (currently Opus 5, Sonnet 5, Haiku 4.5), plus per-harness ids and Codex `model_reasoning_effort`. |
| C | One orchestrator source | `coordination/orchestrator.md` (from the new template) and `orchestrator.json` v2.0 carry the spawn protocol, model classes, per-agent spawn profiles, and routes. `CLAUDE.md` and `AGENTS.md` only point to them. |
| D | Token optimisation | Generated agents are 62% smaller (268 KB -> ~101 KB). The `auto` skill is ~80% smaller (51 KB -> ~10 KB) and is now a closed state machine. Shared rules moved to `contracts/agent-runtime.md`. Long templates moved to on-demand `capabilities/agents/refs/`. Agent listing descriptions are cut to the first sentence. ## 2. Breaking changes

1. **Generated Claude frontmatter shape.** Regenerate `.claude/`. Hand-edited copies in cells will be overwritten by sync, as before.
2. **`orchestrator.json` schema 1.0 -> 2.0.** `agents[]` now carries `summary/inputs/outputs/spawn/definition`. The top-level `model_class` and `description` are gone; read them from `spawn.model_class` and `summary`. Runtime keys `active_session*` / `runtime` are preserved across syncs.
3. **Spec layout v5 -> v6.** New specs never create the retired files. Existing v5 specs keep working: the checkers report `SPEC-LEGACY` warnings and read the old files as fallback. Migration: spec-layout -> *Legacy v5 specs*.
4. **`auto` state numbering.** It is now states 0-18 plus the terminals DONE / STOPPED / ABORTED / SUSPENDED. Anything that parsed the old step numbers (1-17) must map to the new table.
5. **`check-run-conformance` human output.** One line per finding, then `Errors: N  Warnings: M`. The JSON keeps the old `code/owner/error_count/warn_count` fields alongside the contract fields.
6. **Claude settings template.** Adds `statusLine`, a `PreToolUse` limit guard (`*`), and an implementation lock (`Write|Edit|MultiEdit|NotebookEdit`). Existing cells keep their hand-edited `.claude/settings.json`; merge these entries in by hand.

## 5. Port procedure

1. Copy all 29 new files and overwrite the 57 modified ones into
   `KCC Repo/.KCC/`. Keep `.sh` files **LF** and `.ps1` files ASCII.
2. `powershell -ExecutionPolicy Bypass -File .KCC\tools\validate-kcc.ps1 -Mode repo`
   and `bash .KCC/tools/validate-kcc.sh`. Expect 0 errors (the contract lint
   included).
3. `framework-init.ps1 -Harness all` in a throwaway folder. Expect 17
   agents / 23 skills per harness, and the generated `.claude/agents/*.md` to
   carry `name/model/effort/tools`.
4. Run the fixture suites. The fixtures used during development are
   described in section 6; recreate them as repo tests (recommended next step).
5. Update the repo docs (`README.md`, `QUICKSTART.md`, `PLAN.md`) with
   `/bug-report`, `auto resume`, `repo-bootstrap`, `kcc-handover`,
   `kcc-limit-watch`, and spec layout v6.
6. Bump the framework version (suggest v0.5: breaking changes 2-4).

  `Contract drift` in both shells.
- `sync-adapters.ps1 -Harness all`: Claude 41, Codex 65, OpenCode 64, generic

- Check tools: valid fixture exits 0 on every scope; broken fixture exits 1
  with every expected ID. PS 5.1, pwsh, and bash agree. Impl-lock tested in

- `quality-gate`: deferred path (exit 3) and the built-in secret fallback

  connect-remote / skip tested; credential-bearing URLs are rejected. The
  pre-commit hook blocked a fake AWS key.
- Continuity: status line at 42/96/99.5%; guard allow/soft/hard; restore
  points plus git tags; the detached watcher resumed a fake `claude -p
  --resume` after the reset; `-Wrap` parsed 7 reset-message formats;
  bypass templates are refused; handover dry-run works for all four targets.

## 7. Known limitations and follow-ups

1. **Scanner parsing verified on Windows** (gitleaks 8.30.1, osv-scanner
   2.4.0, semgrep via Docker). Planted issues were detected: a secret, 7 high
   dependency groups, and 3 SAST errors. Still open: syft/trivy (deployables),
   the macOS/Linux scanner runs, and the pinned scanner versions in the CI
   templates. The **built-in secret fallback** (used only when gitleaks is
   absent) missed a generic high-entropy assignment. It is a weak backstop,
   so treat gitleaks as required on developer machines and in CI.
2. **Codex and OpenCode expose no usage data.** The watcher relies on
   rate-limit error text (`-Wrap`) or `default_wait_minutes`. OpenCode's
   `run --session` and the interactive flags are unverified. `generic` has no
   default resume template.
3. **Headless `claude -p` doesn't run the status line,** so `usage.json` goes
   stale in unattended runs. The watcher falls back to output patterns and CPs.
4. **Detached watcher survival** after the parent harness exits is untested
   on all OSes.
5. **`sync-adapters.sh` is slow on Git Bash** (minutes) and was observed
   exiting 1 after generating its outputs once. Investigate; the PS version
   takes under 2 seconds.
6. **Narrow Bash scopes.** Claude subagent `tools:` accepts bare names only.
   Per-agent `Bash(git log*)` intent is published as `exec_scope` in
   `orchestrator.json`; enforce it with `.claude/settings.json` permission
   rules if needed.
7. **Loop counters** moved from `budget.md` to the trace
   (`TokenUsage.md -> ## Trials counter`) and are carried across sessions by
   restore points.

## 8. Deterministic driver `kcc-run` (added in the same round)

| Path | Change | Purpose |
|--|--|--|
| `kernel/auto-states.json` | new | Machine-readable state table (states 0-18, checks, gates, events); the twin of the `auto` skill table |
| `kernel/protocols/kcc-run.md` | new | Runner protocol: CLI, exit codes, files, gates, limits |
| `tools/kcc-run.{ps1,sh}` | new | Runs each state headlessly through the harness CLI (`continuity.start`, never a bypass flag), then its exit-check tool. Skips states that already pass (safe resume). Retries with the violation list (max 3), then the `loop` gate. Gates are `coordination/gates/GATE-NNN.md`, answered with `-Answer`. REVIEW failure goes back to IMPLEMENT. On a usage limit: `limit-hard` CP, then arms `kcc-limit-watch -Command "kcc-run -Resume"` |
| `tools/backchannel-append.sh` | modified | Per-line `sed` loop replaced by one pipeline (6.5 s -> 0.5 s per event on Git Bash) |
| `settings.json`, `templates/settings.json.template` | modified | New `run` section (max_attempts, state_timeout_minutes, harness) |

**CLI:** `kcc-run -Input <idea|path|IDEA-ID|SPEC-ID|all> [-Silent -Assume]
[-Accuracy NN] [-Budget NN -Currency CCY] [-Parallel] [-Harness ...] [-Resume]
[-Answer <choice>] [-From N] [-Only N] [-DryRun] [-Json]` (bash:
`--kebab-case`).
**Exit codes:** 0 done / dry-run, 2 usage, 4 paused at a gate, 5 suspended
(usage limit), 6 stopped or aborted. Run state lives in
`coordination/run/run.json`, and logs in `coordination/run/logs/`.

**Verified (PS 5.1, pwsh 7, bash; fake harness in a fixture):**
- Dry-run lists states x specs x waves and writes nothing (also checked on a
  real workspace).
- S2 runs from state 0 to DONE.
- S1 pauses at interactive states, CONFIRM, the budget gates, and WINDOWS;
  `-Answer` continues, and an invalid answer exits 2.
- Retry-then-pass works; 3 failures open the `loop` gate, and `revise`
  recovers.
- REVIEW failure replays IMPLEMENT waves.
- Quality-gate exit 3 opens the deferred gate.
- A usage-limit message leads to exit 5, a CP, and an armed watcher;
  `-Resume` continues.
- The S3 budget cap gates, and `increase` continues.
- `-Only` and `-From` work.

**Limitations:**
1. Specs and waves run sequentially in v1. The ROADMAP parallel lanes are not
   yet fanned out by the runner (the in-harness `auto` skill still fans out).
2. In the runner tests the gate tools were stubbed by artifact-driven fakes.
   Each tool was tested on its own (section 6), but an end-to-end run with a
   real harness is still pending.
3. Bash is slow on Git Bash (~5 min for the S2 fixture), mostly process
   start-up and the dashboard rebuild on each gate event.
4. `kcc-checkpoint` has no per-state reason. The runner writes
   `spec-reviewed` after REVIEW and a `manual` baseline before each wave (the
   wave-scope base).
5. A resume command whose paths contain spaces depends on
   `kcc-limit-watch` quoting. Test it on such paths.

Total for this round, including section 8: **58 changed, 33 new** against the
baseline.

## 8b. SAST through Docker (Windows)

semgrep has no native Windows build. `quality-gate.{ps1,sh}` now reads
`quality.scanners.sast_runner` (`local` by default, or `docker`). With
`docker` and no local semgrep, it runs `docker run --rm -v <ws>:/src -v
<artifacts>:/out semgrep/semgrep semgrep scan --config auto --json ...`. The
template default stays `local`; set `docker` per cell on Windows.
